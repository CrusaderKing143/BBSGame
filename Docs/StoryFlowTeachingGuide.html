用最简单的数据结构搭建论坛剧情循环

以当前 BBSGame 项目为案例，学习如何把一个职责过多的 StorySystem，拆成学生能够读懂、配置和继续扩展的线性剧情系统。

GameObject 显示与隐藏 Button 点击事件 [Serializable] 数据结构 数组与索引 职责分离
适用对象Unity 初学者 / 中职、高职或本科低年级

教学方式讲解、演示、结对调试、独立扩展

01学情与项目分析

学生已有基础

  • 会在 Hierarchy 中创建和查找 GameObject。
  • 知道 SetActive(true/false) 可以显示或隐藏对象。
  • 接触过 MonoBehaviour、Start() 和 UGUI Button。
  • 能够在 Inspector 中拖拽引用，但对“数据”和“流程”为什么要分开还不熟悉。

真实项目问题

旧脚本把邮件数据、帖子数据、按钮绑定、页面切换、剧情进度和选择分支全部写进同一个 StorySystem。脚本越写越长，修改一个功能时容易影响其他功能。

本课核心问题 如果一个脚本同时负责“记住数据、保存进度、控制邮件、控制论坛、决定下一步”，我们怎样把它拆开，又不使用学生暂时难以理解的高级框架？

目标剧情流程

1. 邮箱初始只有邮箱 Icon 可用，玩家阅读当前邮件。
2. 论坛邮件读完后论坛 Icon 解锁，首次显示欢迎页。
3. 帖子帖子按照 1、2、3 的顺序逐个出现。
4. 下一轮最后一帖返回后回到主页面，出现下一封邮件。

02教学目标

知识目标

  • 理解数据、状态、界面和流程四种职责。
  • 理解 [Serializable]、数组和索引的作用。
  • 理解 Button.interactable 与 SetActive 的区别。

能力目标

  • 能够在 Inspector 中配置一轮邮件和帖子。
  • 能够跟踪当前轮次和帖子解锁进度。
  • 能够根据现象定位引用为空、索引错误和状态错误。

素养目标

  • 形成“一个脚本只做一类事情”的意识。
  • 养成先画流程、再写代码、最后测试的习惯。
  • 认识可读命名对团队协作的重要性。

03教学重点与难点

教学重点
  1. 用 StoryRoundData 表示“一轮剧情”。
  2. 用 StoryProgress 保存当前进度。
  3. 让界面控制器只处理 GameObject 显示和隐藏。
教学难点
  1. 理解“数组索引就是内容顺序”。
  2. 理解打开旧帖子不能再次推进剧情。
  3. 理解返回最后一帖时为什么要重置本轮状态。

新系统没有使用 ScriptableObject、事件总线或复杂状态机，只使用普通类、MonoBehaviour、Button 和 GameObject。

05数据结构教学

5.1 一封邮件需要什么？

邮件列表中的按钮负责“被点击”，邮件内容 GameObject 负责“被显示”。因此一封邮件只需要两个引用。

[Serializable]
public class MailData
{
    public Button button;
    public GameObject contentImage;

    public bool IsValid => button != null
        && contentImage != null;
}
课堂提问 为什么不能只保存邮件内容图片？因为程序还需要知道玩家点击的是哪个邮件按钮。

5.2 一个帖子与邮件结构相同

[Serializable]
public class PostData
{
    public Button button;
    public GameObject contentImage;
}

5.3 一轮剧情 = 一封邮件 + 若干帖子

[Serializable]
public class StoryRoundData
{
    public MailData mail;
    public PostData[] posts;
}
数组索引代表的内容什么时候出现
posts[0]第一个帖子读完邮件后
posts[1]第二个帖子从第一个帖子返回后
posts[2]第三个帖子从第二个帖子返回后
为什么不用 ScriptableObject？
本项目的内容全部已经放在一个场景中，邮件和帖子都是场景 GameObject。直接在 Inspector 中拖拽引用最直观，也最适合初学者。未来当章节很多、需要跨场景或外部表格配置时，再学习 ScriptableObject。

06五个脚本的职责与读法

数据层

StoryData.cs

定义 MailData、PostData 和 StoryRoundData。它只描述“有什么”，不处理点击。

阅读关键词： Serializable、Button、GameObject、数组。
状态层

StoryProgress.cs

记录当前轮次、已解锁帖子、当前打开帖子、邮件是否已读和论坛是否进入过。

阅读关键词： int、bool、索引、状态重置。
邮件界面

MailPanelController.cs

只控制邮件面板、邮件按钮和邮件内容图片的显示隐藏。

阅读关键词： ShowPanel、ShowContent、HidePanel。
论坛界面

ForumPanelController.cs

控制欢迎页、帖子列表、帖子内容和帖子按钮可见性。

阅读关键词： unlockedPostIndex、HideAllPostContents。
流程协调

StoryFlowController.cs

绑定按钮、询问 StoryProgress 是否允许操作，再通知两个界面控制器显示正确页面。它是“总指挥”，但不亲自处理所有细节。

阅读关键词： BindButtons、OpenMail、OpenPost、BackFromPostContent、RefreshView。

6.1 状态变量逐项解释

变量示例含义
CurrentRoundIndex0正在进行第一轮剧情。
UnlockedPostIndex1第 0、1 号帖子都已经解锁。
OpenedPostIndex1玩家当前打开的是第二个帖子。
MailReadtrue当前轮邮件已经阅读。
ForumJoinedtrue欢迎页已经看过，后续直接进入帖子列表。

6.2 最关键的推进判断

bool openedLatestPost =
    OpenedPostIndex == UnlockedPostIndex;

if (openedLatestPost && UnlockedPostIndex < postCount - 1)
{
    UnlockedPostIndex++;
}

只有打开“目前最新解锁的帖子”并返回，才会让索引加一。重新阅读旧帖子不会推进，避免玩家重复解锁剧情。

6.3 按钮绑定中的局部变量

int capturedPostIndex = postIndex;
AddClick(round.posts[postIndex]?.button,
    () => OpenPost(capturedRoundIndex, capturedPostIndex));

每个按钮都要记住自己的轮次和帖子编号。课堂上可以让学生打印编号，观察不同按钮传入的索引。

07课堂教学过程

环节一：情境导入与问题发现

10 分钟

教师活动：演示旧 StorySystem，要求学生圈出其中的数据、状态和界面代码。

学生活动：小组讨论“为什么脚本越来越难修改”。

形成结论：不是代码行数本身有问题，而是一个脚本承担了太多不同职责。

环节二：先画剧情流程

15 分钟

教师活动：在黑板写出“邮件 → 论坛 → 帖子1 → 帖子2 → 帖子3 → 下一封邮件”。

学生活动：指出每一步需要记住的数据，例如“当前是第几轮”“目前解锁到第几个帖子”。

检查问题：如果玩家重新打开帖子1，应该解锁帖子3吗？答案：不应该。

环节三：建立三层数据结构

25 分钟

教师活动：从 MailData 开始，逐步组合出 PostData 和 StoryRoundData。

学生活动：在纸上画包含关系，再在 Inspector 中观察嵌套数组。

即时评价：学生能用一句话解释“为什么 posts 使用数组”。

环节四：实现 StoryProgress

25 分钟

教师活动：用具体数值演示索引变化：-1 → 0 → 1 → 2。

学生活动：手动模拟打开帖子、返回帖子、切换轮次。

难点突破：-1 表示“还没有任何帖子解锁或打开”。

环节五：拆分邮件与论坛界面

20 分钟

教师活动：演示两个 PanelController 只调用 SetActive，不改变剧情轮次。

学生活动：分别找出邮件控制器和论坛控制器负责的 GameObject。

检查问题：界面控制器能否自己决定进入下一轮？答案：不能，由流程控制器决定。

环节六：流程协调与按钮绑定

25 分钟

教师活动：跟踪一次完整点击链：Button → StoryFlow → StoryProgress → PanelController。

学生活动：给关键方法画调用箭头，并用 Debug.Log 输出当前索引。

环节七：Inspector 配置与验收

15 分钟

教师活动：演示三轮邮件配置，强调第一轮有3帖，后两轮暂为空。

学生活动：运行场景，按验收清单逐项测试。

08Inspector 配置指南

8.1 MainPanel 上的组件

  • 挂载 StoryFlowController。
  • 挂载 MailPanelController。
  • 挂载 ForumPanelController。
  • Mail Button 拖入 MailIconButton。
  • Forum Button 拖入 ForumIconButton。
  • Picture Button 拖入 PictureIconButton，由脚本保持禁用。

8.2 当前三轮数据

RoundMailPosts运行结果
Element 0MailButton_01 + MailContent_01PostButton_01～03 及对应内容可以完成一整轮。
Element 1MailButton_02 + MailContent_02空数组邮件可读，论坛保持禁用。
Element 2MailButton_03 + MailContent_03空数组作为第三轮内容插槽。
配置原则 一个 Post 元素必须同时配置 Button 和 Content Image。只配置其中一个时，该轮论坛不会解锁，以免玩家进入后卡住。

8.3 添加第二轮帖子

  1. 复制或新建帖子按钮 GameObject，并命名为 PostButton_04 等清晰名称。
  2. 新建对应帖子内容 GameObject，初始设置为不激活。
  3. 展开 Story Rounds → Element 1 → Posts。
  4. 设置数组 Size，并按照剧情顺序拖入 Button 与 Content Image。
  5. 运行后重新阅读第二封邮件，论坛 Icon 才会可点击。

09调试方法与常见错误

现象可能原因排查方法
邮箱 Icon 无法点击当前轮邮件 Button 或 Content 未配置检查 Story Rounds 当前 Element 的 Mail。
读完邮件后论坛仍不可点击Posts 为空，或某个 Post 引用不完整检查数组 Size、Button、Content Image。
多个帖子内容同时出现打开前没有隐藏其他内容确认调用了 HideAllPostContents。
重新阅读邮件后帖子进度丢失每次读邮件都把索引重设为0只在 UnlockedPostIndex 小于0时设置为0。
点击旧帖子也会解锁新帖没有判断是否打开最新帖子比较 OpenedPostIndex 与 UnlockedPostIndex。
第二轮进入论坛后是空白第二轮没有配置帖子本项目默认保持论坛禁用，不自动跳过。

推荐调试输出

Debug.Log($"Round={progress.CurrentRoundIndex}, "
    + $"UnlockedPost={progress.UnlockedPostIndex}, "
    + $"MailRead={progress.MailRead}");
学生调试三问
  1. 数据有吗？ Inspector 引用是否为空？
  2. 状态对吗？ 当前轮次和索引是否符合预期？
  3. 界面刷新了吗？ 改完状态后是否调用 RefreshView？

10分层练习与课后任务

基础任务

  1. 为第二轮添加2个帖子。
  2. 确认两个帖子逐个解锁。
  3. 用 Debug.Log 输出索引变化。

提高任务

  1. 增加“未读邮件”红点 GameObject。
  2. 读完邮件后隐藏红点。
  3. 进入下一轮时显示下一封邮件红点。

挑战任务

  1. 增加剧情完成面板。
  2. 最后一轮最后一帖返回后显示该面板。
  3. 不要加入分支系统，保持线性结构。

课堂思考题

1. 为什么轮次切换时不把 ForumJoined 设回 false？
因为欢迎页只要求第一次出现。切换轮次只重置当前轮状态，完整 ResetStory 才重置整个游戏状态。
2. 为什么内容图片使用 GameObject，而不是只使用 Image？
当前帖子内容可能是带 Scroll View、文字和多张图片的完整层级。控制根 GameObject 更通用，也仍然符合初学者的 SetActive 思路。
3. 为什么不能把帖子按钮全部设为 interactable=false，而是直接隐藏未解锁帖子？
这是当前产品表现要求：第二、第三个帖子在剧情推进后才“出现”。如果设计要求提前可见但不可点，则可以改用 interactable。

11学习评价标准

评价维度优秀达标需改进分值
数据配置轮次、邮件、帖子顺序全部正确主要引用正确，少量命名不规范引用缺失或顺序错误20
流程实现完整实现逐帖解锁与轮次切换主流程可运行存在卡死或越级解锁30
代码理解能解释五个脚本的职责边界能说明主要方法作用只能模仿，无法解释20
调试能力能用日志和状态定位问题能根据提示修复引用问题缺少基本排查步骤20
规范与表达命名清晰，演示讲解完整基本规范命名混乱，缺少说明10

形成性评价记录

  • 能够在不看答案的情况下画出完整流程。
  • 能够解释 UnlockedPostIndex = -1 的含义。
  • 能够独立添加一轮新邮件和帖子。
  • 能够说明为什么重新阅读旧帖子不推进剧情。

12板书设计与课堂小结

一轮剧情 StoryRoundData
├── MailData
│   ├── Button
│   └── Content GameObject
└── PostData[]
    ├── Post 0
    ├── Post 1
    └── Post 2

数据：有什么？          StoryData
状态：进行到哪里？      StoryProgress
界面：显示什么？        Mail / Forum PanelController
流程：下一步做什么？    StoryFlowController

推进条件：OpenedPostIndex == UnlockedPostIndex
课堂小结 好的拆分不是脚本越多越好，而是每个脚本都能用一句简单的话说明职责。本项目最终仍然只依赖学生熟悉的 GameObject、Button、数组和 if 判断。

教师课后反思提示

  • 学生是否真正理解索引，还是只会照着拖 Inspector？
  • 是否需要增加一次“故意留空引用”的排错练习？
  • 学生是否能区分隐藏 GameObject 与禁用 Button？
  • 下一课可衔接：未读红点、剧情完成状态或简单存档。
